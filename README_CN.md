# Typorian Image

让 Obsidian 与 Typora 共用同一批 Markdown 笔记的图片插件。插入的图片保存到笔记同级的 `${notename}.assets/` 文件夹，链接使用标准 Markdown 图片语法。

当前源码版本为 **1.7.0**。本机安装与实际运行验收的状态单独记录在[实施检查报告](docs/optimization-review-2026-10-08.md)，不能从版本号推断正式 Release 已发布。

## 功能

- 粘贴、拖入 PNG、JPEG、GIF、WebP、SVG、BMP、TIFF 图片。
- 保留原始文件名或采用时间戳命名；启用冲突重命名时追加编号。
- 多图按输入顺序一次插入；粘贴替换选区，拖入在落点插入。
- 异步插图绑定产生事件的编辑器及笔记。
- 隐藏文件列表中的 `.assets` 文件夹，图片与链接保留原样。
- 检查无主图片，修复当前笔记或全库笔记的失效图片链接。
- 预览并选择转换 Wiki 图片链接。
- 将笔记与引用图片导出为文件夹或 ZIP。
- 将所选笔记的图片整理到各自的 `.assets` 文件夹，支持生成副本或原地整理。
- 中英双语、自定义附件路径及可选侧栏工具。

## 安装

从已发布的 GitHub Release 下载 `main.js`、`manifest.json`、`styles.css`，放入 `<笔记库>/.obsidian/plugins/typorian-image/`，然后在 **设置 → 第三方插件** 中启用。源码版本号或草稿 PR 不代表同版本安装包已经正式发布。

也可以安装 BRAT，在 **Add Beta Plugin** 中填写 `ygttygtt/typorian-image`。

## Typora 配置

在 **Typora → 偏好设置 → 图像** 中选择“复制图片到自定义文件夹”，填写：

```text
./${filename}.assets/
```

Obsidian 插件保持默认资源路径：

```text
./${notename}.assets/
```

两个编辑器即可使用同一笔记旁的图片目录。既有图片不批量改名，普通笔记双链维持原有行为。

## 插图与设置

| 设置 | 默认值 | 实际行为 |
| --- | --- | --- |
| 图片命名策略 | 保留原始文件名 | 保留名称或采用时间戳；不兼容桌面文件名或链接语义的字符改为 `_` |
| 冲突时自动重命名 | 开启 | 追加 `(1)`、`(2)` 等编号；关闭后跳过冲突图片并提示，不覆盖旧图片 |
| 资源文件夹路径 | `./${notename}.assets/` | 相对于接收事件的笔记解析模板 |
| 隐藏 `.assets` 文件夹 | 关闭 | 隐藏文件列表中名称以 `.assets` 结尾的目录 |
| 扫描代码块 | 关闭 | 修复、转换默认跳过代码示例；需要时可主动开启 |
| 重构副本目录 | `_Restructured_Vault` | 库内相对目录；每次生成副本采用唯一输出目录 |

新插入图片的名称会按 Obsidian 与桌面文件系统的兼容规则处理。已有图片不整体改名。生成链接时统一编码空格、中文、字面 `%`、括号等字符；输入语法包含的图片说明和标题会保留。

多张图片先按序保存，再一次插入链接。混合图片与其他附件的拖入交由 Obsidian 处理，避免丢弃其他附件。异步插入会跟随接收编辑器的文本变化；保存期间若该编辑器切换笔记或关闭，图片仍属于事件捕获时的笔记，并显示该笔记路径提示，不把链接写入另一篇文档。

隐藏仅影响文件列表，图片保留在磁盘上，Obsidian、搜索与 Typora 仍可访问。新建或重命名的 `.assets` 目录自动匹配，弹出窗口采用同一设置。此功能需要 Obsidian 安装器支持 CSS `:has()`；具体已验收及待验收场景见实施检查报告。

## 无主图片与失效链接

从侧栏或命令面板打开 **Image Audit**。当前笔记模式只显示该笔记配置附件目录及其子目录中的候选图片；全库模式显示库内 `.assets` 目录中的候选图片。引用判断始终结合全库笔记，因此其他笔记共用的图片仍视为有引用。

扫描结合 Obsidian 已解析链接索引与当前笔记正文，只在用户请求时执行，没有新增后台循环。默认不勾选图片。清理前重新确认所选图片的引用状态，将仍无引用的所选图片移入 Obsidian 内部 `.trash`。恢复需从 `.trash` 文件中找回，插件不提供恢复界面。

修复先按明确路径查找图片；路径不存在时，仅当全库恰好一个同名图片时使用该图片。出现多个同名候选时保留原链接，不自动选第一张。Wiki 显式路径按路径解析，可配置手动附件目录参与解析。默认跳过代码块及行内代码中的示例。

独立 Wiki 转换面板支持逐项预览与选择。同样文字重复出现时按各自位置处理，避免误替换第一处；扫描后笔记正文发生变化，需要重新扫描后操作。

## 分享导出

分享窗口填写的是**库内相对父目录**，留空表示库根。绝对系统路径和包含 `..` 的目录不受支持；此窗口不提供库外导出。

文件夹方式生成 `<父目录>/<笔记名>/`，其中包含 Markdown 文件和 `<笔记名>.assets/` 图片目录；ZIP 方式生成 `<父目录>/<笔记名>.zip`。再次导出会生成唯一名称，提示显示真实结果路径。

不同来源的同名图片采用不同输出名称；同一来源被重复引用时只打包一份。Markdown 和 Wiki 图片都可纳入；远程图片、无法解析的链接及代码示例保留原文。导出不修改原笔记和图片。

## 附件重构

在设置中启用附件重构工具，打开预览并选择含有可解析图片的笔记。

- **副本模式：** 在配置目录基础上创建新的唯一输出目录，保留笔记路径，为每篇所选笔记复制完整图片集。后续扫描排除以前生成的重构输出目录。
- **原地模式：** 只改写所选笔记的图片链接，将引用图片复制到该笔记同级 `.assets` 目录。已经在正确目录的图片复用，目标同名文件采用唯一名称。

原地整理保留来源图片，供未选择的笔记及其他链接继续使用，不自动回收原图。随后可通过无主图片工具单独检查不再引用的 `.assets` 图片；位于 `.assets` 之外的来源图片不在该工具清理范围内。无法解析的图片链接不会改写为不存在的目标。

## 源码构建

```bash
git clone https://github.com/ygttygtt/typorian-image.git
cd typorian-image
npm install
npx tsc --noEmit
npm run build
```

默认参数及图片名称规则统一位于项目根 `settings.ts`。用户设置通过 Obsidian 插件数据 API 保存，不依赖环境变量注入参数。共享 Markdown/Wiki 解析位于 `src/markdown-images.ts`，路径编码及解析位于 `src/path-utils.ts`。

项目没有配置测试框架。通过现有类型检查、生产构建、源码复核与直接操作 Obsidian 验证；构建成功不单独代表本机运行验收完成。

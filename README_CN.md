# Typorian Image

让 Obsidian 与 Typora 共用同一批 Markdown 笔记的图片插件。插入的图片保存到笔记同级的 `${notename}.assets/` 文件夹，链接使用标准 Markdown 图片语法。

当前源码版本为 **1.8.4**。本机安装与实际运行验收的状态单独记录在[图片检查实施计划](docs/superpowers/plans/2026-10-08-image-check-workflow.md)，不能从版本号推断正式 Release 已发布。

## 功能

- 粘贴、拖入 PNG、JPEG、GIF、WebP、SVG、BMP、TIFF 图片。
- 保留原始文件名或采用时间戳命名；启用冲突重命名时追加编号。
- 多图按输入顺序一次插入；粘贴替换选区，拖入在落点插入。
- 异步插图绑定产生事件的编辑器及笔记。
- 隐藏文件列表中的 `.assets` 文件夹，图片与链接保留原样。
- 统一检查失效图片引用与未引用图片，支持当前笔记及全库范围。
- 预览并选择转换 Wiki 图片链接。
- 将笔记与引用图片导出为文件夹或 ZIP。
- 将所选笔记的图片整理到各自的 `.assets` 文件夹，支持生成副本或原地整理。
- 中英双语、自定义附件路径及可选侧栏工具。

## 安装

从已发布的 GitHub Release 下载 `main.js`、`manifest.json`、`styles.css`，放入 `<笔记库>/.obsidian/plugins/typorian-image/`，然后在 **设置 → 第三方插件** 中启用。源码版本号或草稿 PR 不代表同版本安装包已经正式发布。

也可以安装 BRAT，在 **Add Beta Plugin** 中填写 `ygttygtt/typorian-image`。

## Typora 配置

在 **Typora → 偏好设置 → 图像** 中选择“复制图片到自定义文件夹”，填写：

```text
./${filename}.assets/
```

Obsidian 插件保持默认资源路径：

```text
./${notename}.assets/
```

两个编辑器即可使用同一笔记旁的图片目录。既有图片不批量改名，普通笔记双链维持原有行为。

## 插图与设置

| 设置 | 默认值 | 实际行为 |
| --- | --- | --- |
| 图片命名策略 | 保留原始文件名 | 保留名称或采用时间戳；不兼容桌面文件名或链接语义的字符改为 `_` |
| 冲突时自动重命名 | 开启 | 追加 `(1)`、`(2)` 等编号；关闭后跳过冲突图片并提示，不覆盖旧图片 |
| 资源文件夹路径 | `./${notename}.assets/` | 相对于接收事件的笔记解析模板 |
| 隐藏 `.assets` 文件夹 | 关闭 | 隐藏文件列表中名称以 `.assets` 结尾的目录 |
| 转换时包含代码示例 | 关闭 | 仅作用于主动 Wiki 格式转换；图片检查始终跳过代码示例 |
| Wiki 转换 / 附件重构侧栏快捷入口 | 关闭 | 可选快捷入口；命令面板与“更多工具”始终可用 |
| 重构副本目录 | `_Restructured_Vault` | 库内相对目录；每次生成副本采用唯一输出目录 |

新插入图片的名称会按 Obsidian 与桌面文件系统的兼容规则处理。已有图片不整体改名。生成链接时统一编码空格、中文、字面 `%`、括号等字符；输入语法包含的图片说明和标题会保留。

多张图片先按序保存，再一次插入链接。混合图片与其他附件的拖入交由 Obsidian 处理，避免丢弃其他附件。异步插入会跟随接收编辑器的文本变化；保存期间若该编辑器切换笔记或关闭，图片仍属于事件捕获时的笔记，并显示该笔记路径提示，不把链接写入另一篇文档。

隐藏仅影响文件列表，图片保留在磁盘上，Obsidian、搜索与 Typora 仍可访问。新建或重命名的 `.assets` 目录自动匹配，弹出窗口采用同一设置。此功能需要 Obsidian 安装器支持 CSS `:has()`；具体已验收及待验收场景见实施检查报告。

## 图片检查与格式转换

从侧栏或命令面板打开 **图片检查**，默认进入打开窗口时捕获笔记的“失效图片引用”页。窗口显示完整笔记路径；打开其他笔记查看原文不会改变操作对象。需要扩大范围时主动选择“全库”；没有当前 Markdown 笔记时不会自动扩大范围。

引用页逐处列出 Markdown 与 Wiki 图片语法，展示笔记、行号、原文、状态、目标候选及图片预览。正常引用不进入列表。唯一同名图片会成为修复候选；多个同名候选需选择。找不到目标时，可以选择库内已有图片作为替代，也可以删除该处引用。重复相同引用仍可单独操作。默认不勾选，批量修复和删除只作用于所选出现位置；删除引用会移除完整图片语法，不删除图片文件。

修复保留 Markdown 说明与标题、Wiki 别名与尺寸。来源文件名不兼容时，修复会在笔记附件目录生成兼容副本并保留原图。操作使用捕获的笔记文件与公开文件 API，阅读模式也可操作。扫描后正文变化的笔记会跳过，需要刷新后处理。网络及库外引用不计为库内缺失，图片检查始终跳过代码示例。

“未引用图片”页的当前笔记范围是其配置附件目录及子目录；全库范围是历史 `.assets` 目录与当前附件规则生成目录的并集。引用判断读取全库事实，其他笔记使用的图片仍算有引用。可能对应失效链接的图片另组显示关联，复用同次扫描结果；关联是提示，不算有效引用，也不要求先完成整库修复。

扫描只在用户请求时进行。清理前重新判断所选图片，将仍未引用的文件移入 Obsidian 内部 `.trash`，反馈数量与体积。恢复需从该目录找回，插件不提供恢复界面。引用判断覆盖支持的库内链接，不承诺识别外部软件或任意 HTML/Canvas 的全部用法。

通过 **更多工具 → 转换图片链接格式** 预览并选择 Wiki 转 Markdown。只有已解析且兼容的图片引用可转换。`|300`、`|300x200` 表示尺寸，标准 Markdown 没有等价尺寸表达，因此保留原文。缺失或不兼容引用交给图片检查，转换窗口没有第二套删除功能。两个工具切换时沿用捕获笔记及当前/全库范围；代码示例开关仅用于主动格式转换。

新用户侧栏默认保留图片检查和分享两个入口。格式转换、附件重构可从更多工具与命令面板进入，也可启用侧栏快捷入口；已有明确显示偏好会保留。命令 ID 保持稳定，原快捷键继续指向对应工具。设置按日常插图、链接解析、输出、快捷入口与图标分组，旧“修复时转换 Wiki”开关已移除。

## 分享导出

分享窗口填写的是**库内相对父目录**，留空表示库根。绝对系统路径和包含 `..` 的目录不受支持；此窗口不提供库外导出。

文件夹方式生成 `<父目录>/<笔记名>/`，其中包含 Markdown 文件和 `<笔记名>.assets/` 图片目录；ZIP 方式生成 `<父目录>/<笔记名>.zip`。再次导出会生成唯一名称，提示显示真实结果路径。

不同来源的同名图片采用不同输出名称；同一来源被重复引用时只打包一份。Markdown 和 Wiki 图片都可纳入；远程图片、无法解析的链接及代码示例保留原文。结果提示实际路径、已打包图片数和未打包引用数。普通 Wiki 图片转成 Markdown；带尺寸 Wiki 保留语法并改写目标路径。导出不修改原笔记和图片。

## 附件重构

从更多工具或命令面板打开附件重构，也可启用其侧栏快捷入口；在预览中选择含可解析图片的笔记。

- **副本模式：** 在配置目录基础上创建新的唯一输出目录，保留笔记路径，为每篇所选笔记复制完整图片集。后续扫描排除以前生成的重构输出目录。
- **原地模式：** 只改写所选笔记的图片链接，将引用图片复制到该笔记同级 `.assets` 目录。已经在正确目录的图片复用，目标同名文件采用唯一名称。

原地整理保留来源图片，供未选择的笔记及其他链接继续使用，不自动回收原图。随后可在图片检查的候选目录范围内单独检查未引用图片。整理保留 Markdown/Wiki 语法及 Wiki 尺寸；预览显示未打包引用数，无法解析的链接保留原文。

## 源码构建

```bash
git clone https://github.com/ygttygtt/typorian-image.git
cd typorian-image
npm install
npx tsc --noEmit
npm run build
```

默认参数及图片名称规则统一位于项目根 `settings.ts`。用户设置通过 Obsidian 插件数据 API 保存，不依赖环境变量注入参数。共享 Markdown/Wiki 解析位于 `src/markdown-images.ts`，路径编码及解析位于 `src/path-utils.ts`。

项目没有配置测试框架。通过现有类型检查、生产构建、源码复核与直接操作 Obsidian 验证；构建成功不单独代表本机运行验收完成。
